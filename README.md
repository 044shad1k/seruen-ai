# Seruen AI — ИИ-помощник по прогулкам в Астане

*Серуен (каз.) — прогулка.*

Хакатон «Build with AI», Астана. Кейс №1 от НИЦ Smart City.

Вы говорите, где вы и сколько у вас времени — система отвечает 1–3 конкретными местами:
почему именно туда, что там делать, сколько это займёт и открыто ли оно сейчас. Плюс
мини-маршрут на 2–3 остановки, который укладывается в ваш бюджет времени.

Главное отличие: **система показывает, на каких данных построила ответ**, и никогда не
пишет «открыто», если в данных часов работы нет.

```
$ python -m seruen.cli --preset mega --query "Я у Mega Silk Way, хочу погулять 45 минут"

1. NU Park  —  586 м, 11 мин пешком
   Почему: 11 мин пешком (586 м), часы работы не подтверждены. Парк в Астане. [источник: данные POI]
   Что делать: Пройдите по главной аллее до дальнего конца и обратно. [идея]
   На месте: ~25 мин · часы: неизвестно · уверенность: средняя
   Не проверено: часы работы не подтверждены, доступность на коляске не размечена
```

## Быстрый старт

```bash
make venv          # .venv + зависимости из requirements.txt
make data          # собрать датасет из OpenStreetMap (~40 секунд)
make enrich        # добавить описания из Wikipedia (необязательно, ~2 минуты)
make run           # открыть приложение на http://localhost:8501
make test lint     # 52 теста офлайн + ruff
```

Приложение работает **без ключа** — в этом случае ответы собираются из данных по шаблонам,
и в интерфейсе честно написано `retrieval-template`. Чтобы включить Gemini:

```bash
cp .env.example .env     # вписать GOOGLE_API_KEY, GEMINI_MODEL
```

## Для кого

- **житель города**: «у меня 40 минут между делами, куда сходить рядом»;
- **родитель**: «гуляю с ребёнком и коляской, нужно что-то близко и без ступеней»;
- **турист**: «2 часа до рейса, что успею посмотреть и вернуться»;
- **удалёнщик**: «тихое кафе поработать час»;
- **компания**: «вечером вчетвером, что-то необычное».

## Как это работает

```
запрос → intent → погода → retrieval (датасет 1171 POI) → generation → мини-маршрут
            ↓                   ↓                              ↓
      Gemini JSON +      жёсткие фильтры +              Gemini JSON с poi_id
      regex-парсер       BM25 + скоринг                 только из кандидатов
      (fallback)         → топ-8 карточек               → валидация → шаблоны
```

**1. Разбор запроса (`core/intent.py`).** Из текста достаются категории (нужные и
нежелательные), бюджет времени, «с ребёнком», размер группы, требование без ступеней,
в помещении или на улице, нужен ли возврат в точку старта, ночное время и язык ответа.
Работает через Gemini с JSON-схемой, но словарно-регулярный парсер — не заглушка: он
основной в demo-режиме и подстраховывает модель по каждому полю отдельно.

**2. Поиск (`core/retrieval.py`).** Это и есть R в RAG, и именно здесь принимаются решения:

- радиус считается **из бюджета времени**: `бюджет − время на месте − 5 минут запаса`,
  пополам при возврате к старту (45 минут → 808 м, 2 часа → 4.7 км);
- дорога не может съесть больше 45% бюджета — иначе в ответ попадают места, куда вы
  дойдёте, но не успеете побыть;
- жёсткие фильтры: расстояние, закрытые места вон, `unknown` остаются с пометкой,
  явный `wheelchair=no` вон, когда нужна доступность, нежелательные категории вон;
- скоринг: `3·совпадение категории + BM25(название+описание+теги) + близость +
  0.5·открыто + погода + контекст` (ребёнок, тишина, розетки, ночь, группа, необычное);
- в генерацию уходят **только топ-8 карточек**. Больше модель не видит ничего.

**3. Генерация (`core/generate.py`).** Gemini получает карточки кандидатов и возвращает
строгий JSON: `poi_id` — перечисление из списка кандидатов, плюс «почему», «что делать»,
минуты, уверенность и источник. Дальше ответ валидируется: несуществующий `poi_id` —
выбросить, дубль — выбросить, уверенность выше качества данных — понизить. Если валидных
рекомендаций не осталось, ответ собирается из шаблонов по данным датасета и помечается
`retrieval-template`. **Пустой ответ пользователю не выдаётся из-за сбоя модели.**

**4. Маршрут (`core/route.py`).** Жадный обход от точки старта. Если не влезает в бюджет —
сначала сокращает время на остановках (до 10 минут минимум), потом убирает остановку.

## Датасет — свой, собирается скриптом

| Показатель | Значение |
|---|---|
| Мест всего | **1171** |
| С часами работы | 317 (27%) |
| Кафе / рестораны | 302 / 385 |
| Детские площадки | 262 |
| Достопримечательности / ТЦ / парки | 66 / 51 / 39 |
| Спорт / театры и кино / музеи / библиотеки | 24 / 24 / 10 / 8 |
| С сайтом / телефоном | 192 / 178 |
| С размеченной доступностью на коляске | 67 (из них 41 — «да») |
| С описанием из Wikipedia | 14 |
| Удалено дублей | 61 |

Сбор: `seruen/collect/overpass.py` → Overpass API по bbox Астаны
(51.02, 71.25, 51.25, 71.65), три зеркала с повторами, сырой дамп с отметкой времени и
sha256 в `data/metadata.json`. Нормализация: `seruen/collect/normalize.py` → схема,
дедупликация по названию в радиусе 50 м, `data/quality_report.json`.

Скрипты сбора написаны **только на стандартной библиотеке** — датасет пересобирается на
голом Python, без установки зависимостей.

Отдельный случай — детские площадки: в OSM они почти всегда без названия, и фильтр
«только именованные объекты» оставлял на всю Астану **одну** площадку. Поэтому они
собираются без этого фильтра и подписываются нами по улице, с пометкой `name_generated`,
которая видна пользователю как «название дано нами».

## Ограничения, о которых честно

1. **Часы работы есть только у 27% мест.** Остальные показываются со статусом «неизвестно».
   Это сознательный выбор: лучше признать незнание, чем отправить человека к закрытой двери.
2. **Розетки, тишина, пеленальный столик в OSM не размечены.** Запрос «тихое кафе с
   розетками» отрабатывается косвенно (wi-fi, тип заведения, не-фастфуд), и в карточке
   прямо сказано, что эти признаки не проверены.
3. **Только пешие маршруты.** Поэтому в сценарии «2 часа до самолёта» система честно
   показывает, что рядом с аэропортом в пешей доступности есть только кафе.
4. **Доступность на коляске размечена у 67 мест из 1171.** Мы исключаем явный `no`,
   поднимаем явный `yes`, остальное помечаем как непроверенное — но не выдаём за доступное.
5. **События и афиша не подключены** — только постоянные места.
6. **Качество «почему» в demo-режиме ниже**, чем с Gemini: это шаблоны по данным.
7. **Координаты way/relation сведены к одной центральной точке** (`out center`), поэтому
   для больших парков расстояние считается до центра, а не до ближайшего входа.
