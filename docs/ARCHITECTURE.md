# Архитектура

## Конвейер одного запроса

```
   запрос пользователя + координаты + бюджет времени
                      │
            ┌─────────▼──────────┐
            │  core/intent.py    │  Gemini JSON-схема, при сбое — словарь+regex
            └─────────┬──────────┘  категории, бюджет, ребёнок, группа, коляска,
                      │             в помещении/на улице, возврат, ночь, язык
            ┌─────────▼──────────┐
            │  core/weather.py   │  Open-Meteo, координаты огрублены до 1.1 км
            └─────────┬──────────┘  → нужен ли приоритет мест в помещении
                      │
            ┌─────────▼──────────┐
            │ core/retrieval.py  │  1171 POI → радиус из бюджета → жёсткие фильтры
            │                    │  → BM25 + скоринг → ТОП-8 карточек
            └─────────┬──────────┘
                      │  только эти 8 карточек видит модель
            ┌─────────▼──────────┐
            │ core/generate.py   │  Gemini: JSON, poi_id = enum из кандидатов
            │                    │  → валидация → при провале шаблоны из данных
            └─────────┬──────────┘
                      │
            ┌─────────▼──────────┐
            │  core/route.py     │  порядок обхода + подгонка под бюджет
            └─────────┬──────────┘
                      │
          карточки + мини-маршрут + панель «какие данные использованы»
```

`cli.advise()` — единственная точка сборки конвейера. И CLI, и Streamlit вызывают её,
поэтому интерфейсы не могут разойтись в логике.

## Модули

| Модуль | Отвечает за | Ключевое решение |
|---|---|---|
| `collect/overpass.py` | запрос к Overpass, 3 зеркала, сырой дамп | только stdlib, чтобы датасет пересобирался без venv |
| `collect/normalize.py` | сырьё → `pois.json`, дедуп, отчёт качества | описание строится из тегов на русском — оно же индексируется BM25 |
| `collect/enrich_wiki.py` | описания из Wikidata/Wikipedia | два прохода: по тегу `wikidata` и геопоиском с матчингом по имени и ≤250 м |
| `core/hours.py` | подмножество `opening_hours` → open/closed/unknown | всё непонятое → `unknown`, никогда не `open` |
| `core/geo.py` | расстояния, минуты пешком, радиус из бюджета | 4.2 км/ч × 1.3 на петляние; дорога ≤45% бюджета |
| `core/intent.py` | запрос → структура | regex-парсер равноправен, а не аварийный |
| `core/retrieval.py` | фильтры и ранжирование | модель видит только топ-8 карточек, без координат пользователя |
| `core/generate.py` | карточки ответа | `poi_id` — enum; невалидное отбрасывается; шаблоны как нижняя граница качества |
| `core/route.py` | мини-маршрут | жадный обход, подгонка под бюджет урезанием времени и остановок |
| `core/weather.py` | текущая погода | любая ошибка → `used: False`, поиск просто игнорирует погоду |
| `app/streamlit_app.py` | интерфейс | сценарии в один клик, карта, панель данных |

## Схема записи POI

```json
{
  "id": "way/460703779",
  "name": {"ru": "Хан Шатыр", "kk": "Хан Шатыр", "en": "Khan Shatyr"},
  "name_generated": false,
  "lat": 51.132533, "lon": 71.403948,
  "category": "mall",
  "osm_subtype": "mall",
  "tags": ["торговый центр", "летняя терраса", "wi-fi"],
  "description": "…",
  "description_source": "osm_tags | wikipedia | generated",
  "hours_raw": "Mo-Su,PH 10:00-23:00",
  "wheelchair": "yes | no | limited | unknown",
  "indoor": true,
  "website": null, "phone": null, "wikidata": "Q1026190",
  "source": {"url": "https://www.openstreetmap.org/way/460703779",
             "license": "ODbL", "fetched_at": "2026-10-19T14:20:47+00:00"},
  "evidence": [{"field": "description", "source_url": "https://ru.wikipedia.org/wiki/…"}]
}
```

`category` — одна из: `park, cafe, restaurant, museum, landmark, viewpoint, playground,
mall, theatre, library, sport, other`. Бары и пабы попадают в `restaurant`, но сохраняют
подтип в `osm_subtype` и слово в `tags` — поэтому для «с ребёнком» они штрафуются, а для
«ночью» поднимаются.

## Контракт поиска

1. `typical_visit` = минимальное время посещения среди запрошенных категорий;
2. `radius = (бюджет − typical_visit − 5) × 70 м/мин ÷ 1.3`, пополам при возврате,
   зажат в диапазон 300…6000 м;
3. жёсткие фильтры: расстояние ≤ радиуса · `closed` исключается · `unknown` остаётся
   с пометкой · `wheelchair=no` исключается при требовании доступности · нежелательные
   категории исключаются · дорога ≤45% бюджета;
4. скоринг = `3·категория + BM25 + близость + 0.5·открыто + 0.8·погода + контекст`;
5. если после фильтров меньше 3 мест — радиус расширяется в 1.8 раза один раз, и это
   видно в панели данных как «радиус был расширен автоматически»;
6. топ-8 идут в генерацию, до 3 попадают в ответ, повтор категории — максимум дважды,
   повтор названия запрещён.

## Контракт генерации

Модель получает: системную инструкцию, запрос пользователя, контекст (бюджет, флаги,
погода, язык) и массив карточек. В карточке — `poi_id, name, category, description, tags,
hours_status, hours_raw, distance_m, walk_min, indoor, wheelchair`. **Координат
пользователя в запросе нет.**

Ответ обязан быть JSON по схеме: `picks[1..3]` из `{poi_id (enum), why, activity,
visit_minutes, confidence, source}` и `note`.

Проверки после ответа:

| Нарушение | Что делаем |
|---|---|
| `poi_id` не из списка кандидатов | выбрасываем рекомендацию |
| повтор `poi_id` | выбрасываем |
| пустое «почему» | выбрасываем |
| `confidence: high`, когда часы `unknown` | понижаем до `medium` |
| `source` или `confidence` вне перечисления | заменяем на безопасное значение |
| `visit_minutes` больше бюджета | пересчитываем по данным |
| не осталось ни одной валидной | целиком шаблонный ответ, `mode: retrieval-template` |

Описания и теги подаются модели как данные, и системная инструкция требует игнорировать
инструкции внутри них.

## Что тестируется

`tests/` — 52 теста, все офлайн, без сети и без модели:

- `test_hours.py` — 24/7, диапазоны дней, переход через полночь, два интервала в день,
  `PH` внутри списка дней, запятая как разделитель правил, открытый конец `08:00+`,
  и главное: мусор никогда не становится «открыто»;
- `test_geo.py` — расстояния, обратимость «минуты ↔ метры», радиус из бюджета, возврат,
  ограничение на долю дороги;
- `test_retrieval.py` — закрытое не проходит, `unknown` проходит с пометкой, далёкое
  отсекается, `wheelchair=no` отсекается, нежелательная категория отсекается, в карточке
  для модели нет координат пользователя;
- `test_validation.py` — выдуманный `poi_id`, дубли, битые перечисления, понижение
  уверенности, шаблонный режим;
- `test_app_smoke.py` — приложение проходит все 5 сценариев брифа без исключений.
